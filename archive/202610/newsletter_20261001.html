Dify — 코드 없이 만드는 AI 에이전트 워크플로우

이번 주 선정 이유 : v1.16.0(2026-07) Agent 오픈 베타 출시와 v1.17.0 E2B 클라우드 샌드박스 추가로 에이전트 역량이 급확장, 사내 문서 자동화 시나리오에 직접 적용 가능한 플랫폼이다. Dify는 오픈소스 에이전틱 AI 워크플로우 빌더다. 코딩 없이 캔버스 위에서 노드를 연결해 LLM 호출, RAG 검색, 조건 분기, 코드 실행까지 조합한 AI 애플리케이션을 만들 수 있다. GitHub Stars 15만 4천 이상, 전 세계 140만 대 이상의 머신에서 가동 중이며, 머스크(Maersk)와 노바티스(Novartis) 등 280개 이상의 기업이 도입했다. 2026년 3월 HSG 주도로 3,000만 달러 투자(기업가치 1억 8,000만 달러)를 유치하며 에이전트 역량 고도화와 기업 전용 제품팀 구축에 박차를 가하고 있다. 최근 v1.16.0에서 Dify Agent 오픈 베타를 발표하며 내장 리눅스 샌드박스에서 코드/셸을 실행하는 스킬 시스템을 도입했고, 이어진 v1.17.0에서는 E2B 클라우드 샌드박스, 워크스페이스 수준 스킬 관리, 프로바이더 중립 트레이싱을 추가했다. 한국에서는 ONS(오픈네트웍시스템)가 공식 파트너로 인프라 설계부터 온보딩까지 지원하고 있으며, 서울 커뮤니티 밋업에 130명 이상이 참석해 국내 관심도를 보여줬다.

핵심 요약

오픈소스 비주얼 빌더 Dify로 RAG, 에이전트, 자동화를 코드 없이 조립하고 바로 배포하기

서연이화 관점
자동차 내장재 1차 부품사에서 AI 에이전트를 만들려면 개발 인력 확보가 첫 번째 허들이다. Dify는 시각적 워크플로우 빌더로 이 진입장벽을 낮추는데, 사양서 검색/공정 로그 요약/공급사 견적 비교처럼 구매/영업/품질 등 여러 부서에서 반복되는 문서 업무를 현업 담당자가 직접 자동화할 수 있다는 점이 주목할 부분이다. 셀프호스팅이면 데이터가 외부로 나가지 않아 기밀 사양서를 다루는 부품사 환경에도 적합하다. [5][6][7][8][9]
KEY CAPABILITIES
1
시각적 워크플로우 빌더
LLM 호출, RAG 검색, 조건 분기, 코드 실행, HTTP 요청 노드를 캔버스에서 드래그앤드롭으로 연결해 AI 파이프라인을 구성한다. 코드 한 줄 없이 프로덕션용 API를 만들 수 있다.
2
내장 RAG 엔진
PDF, Word, 텍스트 파일을 업로드하면 자동 청킹과 임베딩을 거쳐 벡터 데이터베이스에 저장된다. 문서 기반 질의응답 앱을 별도 인프라 없이 구축할 수 있다.
3
에이전트 프레임워크(v1.16.0)
ReAct, Function Calling 두 가지 추론 전략을 지원하고, 내장 리눅스 샌드박스에서 코드와 셸을 실행하는 스킬 시스템을 제공한다.
4
200개+ LLM 호환
OpenAI, Claude, Gemini, Llama 등 200개 이상의 모델을 API 키 하나로 교체할 수 있다. 비용이나 성능에 따라 모델을 자유롭게 전환해 운영 비용을 최적화할 수 있다.
5
원클릭 배포와 모니터링
완성한 워크플로우를 웹앱, API 엔드포인트, 임베드 위젯으로 즉시 발행한다. 대화 로그, 토큰 소모량, 응답 품질을 추적하는 모니터링 대시보드가 내장되어 있다.
USE CASES
1
사내 문서 질의 봇
구매/영업/품질 등 여러 부서가 주고받는 사양서와 거래명세서를 RAG 파이프라인에 올려 자연어로 즉시 검색하는 봇을 만든다. 신규 입사자 온보딩이나 감사 대응 시 문서 탐색 시간을 줄일 수 있다.

공정 로그 이상 알림 워크플로우

3
공급사 견적 비교 에이전트
SCM/구매 담당자가 공급사 견적서를 업로드하면 항목별 단가를 추출하고 이전 계약 대비 변동률을 자동 산출하는 에이전트를 구성할 수 있다. 수동 엑셀 비교 대비 반복 작업을 줄인다.
4
회의록 핵심 추출 자동화
부서를 가리지 않고 쌓이는 회의록과 주간 보고서를 LLM이 핵심 의사결정 사항만 추출해 요약 게시하는 워크플로우다. 후속 조치 항목을 자동 태깅해 누락을 방지한다.

GETTING STARTED
1
로컬 설치
GitHub 저장소에서 Docker Compose 파일을 받아 docker compose up -d 한 줄로 설치한다. 브라우저에서 localhost:80으로 접속하면 초기 설정 화면이 뜬다.
2
모델 API 키 등록
설정 > 모델 공급자 메뉴에서 사용할 LLM의 API 키를 등록한다. OpenAI, Claude, Gemini 등 원하는 모델을 선택할 수 있다.
3
지식 베이스 구축(실전 팁)
지식 베이스에 사내 문서 1~2건을 업로드한다. PDF는 텍스트 레이어가 있는 파일만 RAG 효과가 좋다. 스캔 PDF는 반드시 OCR 변환 후 업로드해야 검색 품질이 나온다.
4
첫 워크플로우 구성
워크플로우 스튜디오에서 '지식 검색' 노드와 'LLM 응답' 노드를 연결해 2노드 파이프라인을 만든다. 미리보기에서 질문을 넣어 응답 품질을 확인한다.
5
앱 게시와 공유
'앱 게시' 버튼을 클릭하면 사내 URL이 생성된다. 동료에게 링크를 보내거나 API 엔드포인트를 사내 시스템에 연동할 수 있다.
PITFALLS
⚠ 노드 그래프 복잡도
시각 빌더지만 분기와 반복이 늘어나면 20노드 이상에서 캔버스가 빠르게 복잡해진다. 워크플로우를 기능 단위로 분리하고, 서브플로우를 활용해 가독성을 유지하는 것이 좋다.
⚠ 샌드박스 네트워크 격리
에이전트 코드 실행 시 보안 샌드박스가 외부 네트워크를 차단한다. 외부 API를 호출하려면 에이전트 프록시 설정(agent_ssrf_proxy)을 별도로 구성해야 한다.
⚠ 에이전트 스프롤 리스크
부서마다 독립적으로 에이전트를 만들면 관리 포인트가 기하급수로 늘어난다. 중앙 거버넌스 없이 워크플로우가 확산되면 보안/비용/품질 통제가 어렵다.
⚠ LLM API 비용 분리
Dify 플랫폼은 오픈소스로 무료지만 LLM API 호출 비용은 별도다. 하루 수백 건 RAG 질의만으로도 월 $200~$500 수준의 토큰 비용이 발생할 수 있어 예산 산정이 선행되어야 한다.
⚠ 데이터 보존과 셀프호스팅
클라우드 버전은 대화 로그가 외부 서버에 저장된다. 사내 기밀 사양서나 거래 정보를 다루려면 Docker/Kubernetes 셀프호스팅이 필수이고, 인프라 운영 역량이 요구된다.
